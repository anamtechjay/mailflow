mailflow — technical architecture review

A reusable library that watches one inbox and, per new email, runs a synchronous single-worker pipeline behind a frozen set of ports. This document goes to the implementation substance: the Protocol surface, the contracts that cannot move after 1.0, and how data and failures route through the spine.

Locked V1: Gmail-only · single-tenant · poll-authoritative (push only wakes the poller) · at-least-once delivery with consumer-side dedupe via idempotency_key. One synchronous worker; no internal concurrency (SYNC_ONLY = True).

The pipeline spine per message: wake → verify → fetch-from-cursor → size-guard → claim → extract → clean → filter → emit → commit. Each stage is a method on Pipeline; each external dependency is a @runtime_checkable Protocol. The core imports no vendor SDK.

1.1The pipeline data flow

A push notification is a wake-signal only: it is verified for identity, then discarded as a content source. The worker re-derives what changed from the durable cursor (historyId), never from the ID inside the ping. Every terminal disposition (emitted / dropped / duplicate / dead_lettered) advances the cursor; non-terminal transient failures do not.

2The port surface — ports as the seam

The whole architecture is one idea: a small core of structural contracts surrounded by swappable implementations. The core depends only on typing.Protocol shapes — Gmail, the in-memory stores, the SQLite cursor store are all just things that happen to satisfy a shape. From core/ports.py: "@runtime_checkable only checks method-name existence and is slow; static typing (mypy strict) is the real conformance gate." The decorators @stable / @provisional stamp __stability__ onto each port (A11) so the frozen surface is machine-readable.

core/ports.py — the structural contracts the core depends on (no vendor imports)
@stable
@runtime_checkable
class MailboxProvider(Protocol):
    def connect(self) -> None: ...
    def sync_streams(self) -> Iterable[StreamRef]: ...
    def fetch(self, stream: StreamRef, cursor: Cursor | None) -> Iterator[RawMessage]: ...
    def message_size(self, msg: RawMessage) -> int | None: ...   # None ⇒ unknown ⇒ fail-closed (B1)

@stable @runtime_checkable
class CursorStore(Protocol):
    def get(self, tenant: str, stream: StreamRef) -> Cursor | None: ...
    def commit_if_ahead(self, tenant: str, stream: StreamRef, cursor: Cursor) -> bool: ...  # strictly monotonic

@stable @runtime_checkable
class DedupeStore(Protocol):          # exactly four methods; in-memory does NOT simulate lease expiry
    def try_claim(self, key: str, lease_seconds: int) -> bool: ...
    def record_attempt(self, key: str) -> int: ...
    def mark_done(self, key: str, ttl_seconds: int) -> None: ...
    def release(self, key: str) -> None: ...

@stable @runtime_checkable
class BlobStore(Protocol):
    def put_stream(self, ref: str, chunks: Iterator[bytes], content_type: str) -> str: ...
    def open(self, ref: str) -> Iterator[bytes]: ...

@stable @runtime_checkable
class SecretProvider(Protocol):
    def get(self, ref: str) -> str: ...

@stable @runtime_checkable
class ContentExtractor(Protocol):
    def extract(self, msg: RawMessage, env: Envelope) -> CleanEmail: ...

@stable @runtime_checkable
class Emitter(Protocol):
    def emit(self, event: EmailEvent) -> object: ...   # the DLQ is just another Emitter sink

# ─── provisional surface: shipped in V1, may still evolve ───
@provisional @runtime_checkable
class WebhookVerifier(Protocol):   # A5 — identity only, never payload trust
    def verify(self, *, headers: Mapping[str, str], body: bytes) -> WebhookIdentity: ...

@provisional @runtime_checkable
class ContentCleaner(Protocol):    # A6 — gentle HTML→text by default
    def clean(self, email: CleanEmail) -> CleanEmail: ...

@provisional @runtime_checkable
class TokenRotationSink(Protocol):  # A8 — persist a rotated refresh token or the next run breaks
    def on_refresh(self, ref: str, new_token: str) -> None: ...

Also @stable: SubscriptionManager (ensure_watch / renew_watch), EnvelopeParser (parse_envelope(msg, tenant) -> Envelope), Filter (attr name + evaluate(env, ctx) -> FilterDecision), Classifier (classify(env, ctx) -> Relevance).

CONTRACT NOTE — A8 shape. The build plan described rotation persistence as an "on-refresh callback on SecretProvider." The frozen tree instead lands it as a separate @provisional port, TokenRotationSink.on_refresh(ref, new_token), leaving SecretProvider.get(ref) -> str untouched. This keeps the @stable read-path frozen and makes the write-path additive — a cleaner seam than widening the existing port.

3Frozen contracts reference

These are the shapes and invariants that cannot change after 1.0 without breaking consumers or the persistence layer. Every row is enforced today in the tree and load-bearing for a downstream module. "Spelled identically everywhere" is a hard rule — the type-consistency anchor in CLAUDE.md.

ContractFrozen shapeWhy it is immutable
Identity idempotency_key = "\|".join((tenant, mailbox, provider_message_id)) The dedupe key. (tenant, mailbox) is included so the same mail in two watched inboxes counts as two arrivals. Change the tuple and every stored claim + every consumer's dedupe table is invalidated.
canonical_id trusted <local@domain> Message-ID, else stable_hash(provider, provider_message_id, mailbox) Always-present surrogate id. The "trusted" test (startswith('<'), endswith('>'), contains @) decides which branch — flipping it silently re-ids historical mail.
Wire event EmailEvent(schema_version, tenant, ordering_key, idempotency_key, email) · SCHEMA_VERSION = "1.1" The public output. Adding idempotency_key was a minor bump (1.0→1.1, additive). Consumers are tolerant readers: refuse an unknown major, ignore unknown fields. Removing/retyping a field is a breaking major.
Extractor seam MimeExtractor.extract_bytes(raw, *, provider, provider_message_id, stream_id, watched_mailbox, …) vs port extract(msg, env) Pipeline._extract dispatches on type: a MimeExtractor → extract_bytes; any other extractor → the port. The Graph adapter implements extract(msg, env) directly — the seam is why it never touches the orchestrator.
Cursor Cursor(value, order); commit_if_ahead rejects order ≤ stored Strictly monotonic resume token. Advances on every terminal disposition, not only emit. The real Firestore/Redis adapter must preserve this or replays go backward.
Dedupe API exactly try_claim / record_attempt / mark_done / release The in-memory store deliberately does not simulate lease expiry — the shape is kept exact so a persistent adapter can add expiry without changing callers.
DLQ counting RunReport.dead_lettered incremented only by add_dead_letter() record() does not count dead-letters; _dead_letter calls both as a paired unit. One poison/oversized message ⇒ exactly one count. A standalone dead_lettered trace anywhere would double-count.
from_ alias from_: Recipient = Field(alias="from") on Envelope & CleanEmail from is a Python keyword; the wire spells it from, the model spells it from_. populate_by_name=True bridges both. Must be spelled identically in every model.
thread_key CleanEmail.thread_key: str ← Gmail threadId / Graph conversationId Carried from RawMessage.thread_key through extraction; subject-normalized fallback. Consumers group conversations on it — adding it later would be a breaking field on the emitted email.
Sync-only SYNC_ONLY = True; ports marked @stable / @provisional; config version Declares V1 single-worker. A future async family is an additive set of ports, never a breaking change to these. The stability stamp makes the frozen surface introspectable.
Why a reviewer should care: in a library, the risk is not the code that works today — it is the promises. Get these shapes right and a new provider, store, or cleaner slots in without touching the core or breaking a consumer. Get them wrong and every consumer pays for the rewrite. Phase 0 freezes exactly this surface before any parallel build begins.

4Error taxonomy & routing

Every mailflow error subclasses MailflowError. V1 adds the three-way operational split (A2) that the pipeline routes on. Provider errors (Gmail/Graph) are re-parented onto these so the orchestrator routes by type, never by HTTP status or attempt-count.

core/errors.py — the operational taxonomy (A2)
class MailflowError(Exception): ...                  # base for everything

class AuthError(MailflowError):      # 401  → refresh-and-retry-once
class PermanentError(MailflowError): # 403/404/410, invalid base64 → DLQ, no retry
class TransientError(MailflowError): # 429/5xx/network → bounded backoff retry

class UnknownKindError(ConfigError): ...

5Reliability & failure isolation

5.1 · DLQ counting — the paired-unit invariant

The single most error-prone spot in the spine. RunReport holds four counters: emitted, dropped, duplicates, dead_lettered. The dead_lettered counter is owned solely by add_dead_letter(); record() deliberately does not count it. So _dead_letter must call both — and only it may.

core/pipeline.py — _dead_letter: emit + count + trace as one indivisible unit
def _dead_letter(self, canonical_id, msg, key, report, *, reason) -> Disposition:
    self.dlq_emitter.emit(EmailEvent(...stub email...))      # DLQ is just another Emitter sink
    self.dedupe_store.mark_done(key, self.config.done_ttl_seconds)
    report.add_dead_letter(DeadLetter(canonical_id=canonical_id, reason=reason, ...))  # ← the ONLY +1
    report.record(self._trace(canonical_id, msg, Disposition.dead_lettered, "dlq", reason=reason))
    return Disposition.dead_lettered
Invariant: one poison / oversized message ⇒ exactly one dead_lettered count. Never emit a standalone dead_lettered trace elsewhere — record() would not count it, but a future change to record() could, double-counting. The pairing is the contract.

5.2 · Per-message isolation — and the known gap

The process stage is isolated: _process wraps each message in try/except and DLQs one bad message at max_attempts without touching its neighbors (tested). The fetch stage is the open gap (B2): a single malformed page/delta record currently aborts the whole stream because the fetch iteration has no per-record try/except. The V1 fix wraps the fetch iterator so a malformed record is DLQ'd individually and the stream continues.

5.3 · Backoff & storm containment (B4)

6Extraction & cleaning seam

6.1 · The extractor dispatch

Extraction is the one place the port shape is deliberately not uniform. The raw-RFC822 path (Gmail) needs the raw bytes plus provider context; the generic port (extract(msg, env)) is what other providers implement. Pipeline._extract dispatches on concrete type — a richer-than-port signature that mypy strict accepts via the ContentExtractor | MimeExtractor union annotation and an isinstance branch.

core/pipeline.py — _extract: type-dispatched seam (richer signature vs the port)
def _extract(self, msg: RawMessage, env: Envelope) -> CleanEmail:
    if isinstance(self.extractor, MimeExtractor):
        email = self.extractor.extract_bytes(
            msg.raw_bytes,
            provider=msg.provider,
            provider_message_id=msg.provider_message_id,
            stream_id=msg.stream.key,
            watched_mailbox=msg.stream.mailbox,
            blob_store=self.blob_store,
            thread_key=msg.thread_key,          # A7: carried from the adapter
        )
    else:
        email = self.extractor.extract(msg, env)      # the port — Graph implements this
    if self.cleaner is not None:
        email = self.cleaner.clean(email)           # A6: ContentCleaner as a real stage
    return email

Note the cleaner runs inside _extract as a pipeline stage — not a post-emit hook. That placement is the A6 contract: cleaning is part of producing the CleanEmail, so the emitted event and the DLQ stub share the same cleaned shape.

6.2 · thread_key mapping (A7)

RawMessage.thread_key is populated by the adapter (Gmail threadId / Graph conversationId) and threaded onto CleanEmail.thread_key during extraction. When the provider gives no thread id, a subject-normalized fallback groups a conversation by its normalized subject line. Consumers group replies on this single field regardless of provider.

6.3 · body_text parity (B5)

V1 is plain-text-only (no HTML sanitizer / renderer in scope), which makes the HTML→text converter load-bearing: an HTML-only email must still yield non-empty body_text, or the product looks empty. The fix is a shared HTML→text converter called from both extractor body-paths, so an HTML-only message produces identical body_text whether it arrived via Gmail's MIME walk or Graph's body field. Today neither path does this — both leave body_text="" for HTML-only mail.

Parity is the point. "Provider-agnostic" is only true if the same email yields the same CleanEmail on either adapter. The shared converter (not two per-provider implementations) is what guarantees that — and is what the golden corpus, authored independently of the extractor, cross-checks.

7Build harness & engineering discipline

The build mirrors the architecture: freeze the contracts serially, then implement behind them in file-disjoint parallel tracks. If parallel work invented the shapes independently the pieces wouldn't fit — so Phase 0 locks signatures and model fields (no behavior), mypy-clean and committed, before anyone fans out.

The five guardrails (every task obeys)

  • TDD, one behavior per cycle: failing test → confirm it fails for the stated reason → minimal impl → green → mypy --strict clean → commit.
  • File-disjoint ownership: each track edits only its own files (table below). Cross-track needs are flagged to the lead, never patched into someone else's file.
  • Bisectability: every commit leaves the whole tree importable and mypy-clean. If module A imports B, B is committed first — even if the plan lists them the other way.
  • Evidence or it's not done: a task is done only when its test passes and a verifier can quote the proof. No green test ⇒ not done.
  • Serialized shared repo: subagents share one .git/index and one .mypy_cache; the lead serializes file-disjoint tracks rather than assuming concurrent commits.

mypy --strict gotchas baked into the discipline

The tree is checked whole (packages = ["mailflow"], strict), so every commit must stay importable. Recurring fixes the team applies proactively: hoist **{"from": x} splats to an explicit dict[str, Any] before unpacking; narrow email…get_payload(decode=True) with isinstance(payload, bytes) before hashing; write xs[0] if xs else None rather than (xs or [None])[0]; widen richer-than-port signatures to a union and isinstance-dispatch (exactly the ContentExtractor | MimeExtractor seam above).

Definition of done for V1: full pytest green · mypy --strict clean on the whole tree · every in-scope item (A2, A4, A5-Gmail, A6, A7, A8-reduced, A10, A11, B1–B5) verified with quoted proof · a live Gmail run (push wakes → poll from cursor → clean → emit with idempotency_key; forged push rejected; oversized/unknown DLQ'd pre-download; 429-storm survives) · docs say at-least-once, no exactly-once claims anywhere.
