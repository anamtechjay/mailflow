1 · The product

What mailflow is

mailflow watches an inbox, and on every new email it fetches, opens, cleans, and hands a tidy structured record to your app — handling the messy parts (auth, throttling, duplicates, broken mail) for you.

Mental model — an automated mailroom: a letter arrives → the clerk is pinged → the clerk fetches it using a durable bookmark (not the ping) → opens it, pulls out the useful parts, discards junk → hands a summary card to the department that asked. Everything below is how that mailroom is built.

Poll-authoritativepush only wakes the poller

What V1 delivers

What you get

  • Reuse, not rebuild: one hardened email connector instead of every team writing their own.
  • Clean inputs: sender, subject, readable body, attachments — no raw-email parsing downstream.
  • Safe by default: broken / oversized / poisonous mail is set aside, not allowed to crash the line.
  • Honest delivery: a duplicate fingerprint on every event so consumers can de-duplicate cleanly.

What V1 unlocks next

  • A proven, provider-agnostic foundation — adding Outlook is an adapter on the same ports.
  • A stable public contract teams can start building products against.
  • A clear, low-risk path to richer features (attachments, filtering, recovery) as fast-follows.

Using it — the consumer's view

The consuming app wires mailflow through one front door — connect() — then reads clean events off it. (Illustrative shape; exact API in the README.)

from mailflow import connect

flow = connect(
    provider="gmail",
    filters=[lambda e: e.to == "support@acme.com"],   # your rules (To/CC/subject, regex)
    clean_fn=my_cleaner,                              # optional HTML→text override
)

for event in flow.run():            # synchronous — one email at a time
    if not already_seen(event.idempotency_key):   # at-least-once ⇒ you de-dupe on this key
        handle(event.email)

What you receive on each turn:

EmailEvent(
    schema_version = "1.1",
    tenant         = "acme",
    ordering_key   = "<thread/best-effort grouping>",
    idempotency_key = "acme|support@acme.com|<provider-msg-id>",   # a string: tenant|mailbox|message-id
    email = CleanEmail(sender, subject, body_text, attachments, thread_key, ...),
)

Delivery is at-least-once: the same email may arrive twice (after a crash/retry), so consumers de-duplicate on idempotency_key. The library does the fetching, cleaning, throttling and error-handling; your code only decides what to keep and what to do with it.

2 · Architecture

Ports & adapters — the core idea

The one idea that explains everything else: mailflow is a small core of frozen contracts (ports) surrounded by swappable implementations. The core knows the shape of a mailbox provider, a webhook verifier, a content cleaner, a store — never a specific vendor. Gmail and Outlook are just two implementations of the same ports.

That is also the build philosophy: freeze the contracts first, then build behind them in parallel. A contract is a signature or model field that, once V1 ships, consumers build against — changing it later breaks them.

Core defines the ports; adapters & stores implement them; the facade wires it together for the consumer.

Why a lead should care: the risk in a library isn't today's working code — it's the promises. Right ports → a new provider/store/cleaner slots in without touching the core or breaking a consumer. Wrong ports → every consumer pays for the rewrite. V1's whole job is to lock the right promises.

The port surface

Ports are @runtime_checkable Protocols. Conceptual signatures (grounded in core/ports.py; exact shapes may differ slightly):

# core/ports.py — the seam every implementation plugs into
class MailboxProvider(Protocol):       # Gmail / Graph
    def connect(self) -> None: ...
    def sync_streams(self) -> list[StreamRef]: ...      # provider-defined granularity (A12)
    def fetch(self, stream, cursor) -> Iterator[RawMessage]: ...
    def message_size(self, msg) -> int | None: ...   # None ⇒ unknown ⇒ fail closed (B1)

class WebhookVerifier(Protocol):         # A5 — returns identity only, never payload trust
    def verify(self, headers, body) -> WebhookIdentity: ...

class ContentCleaner(Protocol):          # A6 — a real pipeline stage
    def clean(self, email: CleanEmail) -> CleanEmail: ...

class SecretProvider(Protocol):
    def get(self, ref: str) -> str: ...
class TokenRotationSink(Protocol):        # A8 (provisional) — persist rotated refresh token
    def on_refresh(self, ref: str, new_token: str) -> None: ...

class BlobStore(Protocol): ...      # content-addressed attachment storage
class CursorStore(Protocol): ...    # durable, monotonic bookmark
class DedupeStore(Protocol): ...    # try_claim / record_attempt / mark_done / release
Design note: A8 token-rotation persistence is modelled as a separate @provisional TokenRotationSink.on_refresh(ref, new_token) port rather than widening SecretProvider — keeping the frozen SecretProvider.get shape intact. The build plan explicitly allowed either path ("extend SecretProvider, or the OAuth token-provider seam"), so this is within plan, not a deviation.

3 · The pipeline, stage by stage

Each stage: what · contract · why it matters · status

1 · Wake signal & webhook verification

A5✓ Gmail verifier landed

"A new-mail ping arrived — but is it really from Google, and is it safe to act on?"

Contract
WebhookVerifier port → returns identity only (verified subscription/mailbox), never payload trust.
V1 impl
Gmail Pub/Sub OIDC-JWT — signature via JWKS, audience, issuer. (Outlook validationToken handshake deferred.)
Why it matters
Push ingestion is internet-facing. Without verification anyone can forge a ping. A verified ping still earns only a wake — never "fetch this exact ID."

2 · Fetch & cursor (the golden rule)

A1A3B6✓ Gmail (Outlook deferred)

"On wake, re-derive what changed from a durable bookmark — never trust the ID inside a ping."

Contract
Cursor is durable, strictly monotonic (commit_if_ahead), advances on every terminal disposition. Gmail = historyId; Outlook = deltaLink.
Why it matters
Pings can be forged, duplicated, or arrive out of order. The bookmark is the only trustworthy "where I stopped," so a crash resumes exactly — no gaps, no re-scans.
V1 status
Gmail re-derives from historyId and commits one cursor per page (B6 ✓). Outlook wake-rewire deferred.

3 · Size guard — fail closed

B1✓ fail-closed landed

"If we can't tell how big an email is, assume it's too big and set it aside — before downloading."

Behavior
Unknown / omitted size ⇒ treat as over-limit ⇒ DLQ before fetch. Implemented in pipeline.py (size ≤ 0 ⇒ dead-letter "size unknown"). Previously an unknown size became 0 and slipped under the ceiling.
Why it matters
"Fail open" on size means an unbounded payload can be pulled into memory and crash the run. Safe default is reject, not guess.

4 · Extract fields & thread key

A7✓ thread_key landed (Gmail)

"Open the envelope, pull out sender/subject/body/attachments — and the ID that groups a conversation."

Contract
New thread_key on CleanEmail; maps Gmail threadId / Outlook conversationId, with a subject-normalized fallback.
Seam
MimeExtractor.extract_bytes(...) for raw RFC822 (Gmail); other providers implement extract(msg, env) directly (Graph). Pipeline._extract dispatches by type.
Why it matters
Without a provider-native thread key, consumers can't reliably tie a reply to its original — conversation grouping breaks.

5 · Clean — HTML → text

A6B5✓ cleaner + parity landed

"Turn an email's HTML into readable plain text — gently by default, aggressively only if asked."

Contract
ContentCleaner port (clean(CleanEmail) -> CleanEmail), wired as a real pipeline stage — not a post-emit afterthought.
Parity (B5)
A shared html_to_text converter backfills body_text via the default cleaner stage (and inline in the Gmail extractor), so an HTML-only email yields non-empty body_text identically across providers.
Why it matters
V1 is plain-text-only (no sanitizer/renderer). If HTML-only mail produced blank text the product would look empty. This stage makes the output usable.

6 · Filter

A10✓ overrides + decorators landed

"Only hand the consumer the emails they actually want."

Built-in
To / CC / subject matching incl. regex; consumers inject their own filters.
How
Filters/cleaners inject as callables via connect(filters=[...], clean_fn=...); the generic overrides= seam and as_filter/as_cleaner decorators are now wired in facade.py/builder.py.

7 · Emit event & idempotency

A4✓ key on wire (1.1)

"Hand the consumer a clean event stamped with a fingerprint so they can spot duplicates."

Contract
idempotency_key surfaced on EmailEvent = (tenant, mailbox, provider_message_id). Wire schema 1.0 → 1.1 (additive).
Delivery
At-least-once, documented honestly. Exactly-once is not promised; duplicates are expected and handled by the key. (Earlier docs that claimed exactly-once have been corrected.)
Why it matters
The emitted event is the public contract. The fingerprint is computed internally already — V1 exposes it so consumers don't rebuild it.

4 · Cross-cutting concerns

Error taxonomy & routing

A2B3✓ taxonomy + routing landed

"Sort every failure into Auth / Permanent / Transient, and react differently to each."

Contract
AuthError · PermanentError · TransientError (subclasses of MailflowError); provider errors re-parented onto them. Now in core/errors.py.
Routing
Wired in pipeline.py: Auth (401) → refresh once, retry · Permanent (403/404/410/decode) → DLQ no-retry · Transient (429/5xx/network) → bounded backoff, then DLQ.
Why it matters
Before this, one bare except retried everything by attempt count — so 410 "gone" and garbled data looped forever. The keystone: B3 and B4 build on it (B3's permanent-classification + B4's backoff plug into this routing).

Reliability — isolation, backoff, storm containment

B2B4✓ landed
DLQ isolation (B2)
One broken/oversized message is set aside alone — never crashes the batch. Counted exactly once. Per-record fetch isolation now skips a poison record (404/410/bad-base64) and continues the stream.
Backoff + storm (B4)
Retry 5xx; exponential backoff + jitter honoring Retry-After; bounded in-flight concurrency cap; and an exhausted-retry storm is contained so it can't abort the run.
Why it matters
The difference between "one bad email" and "the run dies." Before B4, a 429 storm propagated uncaught and took everything down.

Extensibility & stability policy

A8A10A11✓ landed
Overrides (A10)
Generic overrides= mapping to inject any component instance, plus as_filter/as_cleaner decorator sugar.
Token rotation (A8)
An on-refresh persistence callback: a rotated OAuth refresh token is saved, or the next run silently breaks. (Multi-tenant/DWD out of V1.)
Versioning (A11)
Explicit sync-only declaration, provisional/stable port markers, config version field.

Observability

~ light in V1
In V1
Basic structured logs + run-report counters (emitted / dropped / duplicate / dead-lettered).
Deferred
PII redaction (scrubbing bodies from logs) is post-V1; for now, full bodies aren't logged by default.

Engineering discipline (guardrails)

  • TDD, one behavior per cycle: failing test → confirm it fails for the stated reason → minimal impl → green → mypy --strict clean → commit.
  • File-disjoint ownership: each track edits only its own files; cross-track needs are flagged, not patched.
  • Bisectability: every commit leaves the whole tree importable and mypy-clean. If A imports B, commit B first.
  • Evidence or it's not done: a task is done only when its test passes and a verifier can quote the proof.

Glossary

Plain-English definitions for the terms used above.

Library / facade — reusable code other apps plug into; the facade (connect()) is the simple front door.

Consumer — the app that uses mailflow.

Port (Protocol) — a defined "plug shape": any component matching it fits. In Python, a @runtime_checkable Protocol (structural typing — no inheritance needed).

Contract — a promise about a shape/behavior. Breaking it after V1 breaks every consumer.

Webhook / push / Pub/Sub — the internet plumbing that delivers a "you have mail" ping. Gmail uses Google Cloud Pub/Sub.

Poll / delta — instead of waiting for a ping, periodically ask "anything new since last time?" A delta is "what changed."

Cursor / bookmark — durable marker of how far reading got, so a crash resumes without gaps or repeats. Gmail's is historyId; Outlook's is deltaLink.

Page / page-atomic — providers return mail in batches ("pages"); the cursor advances one whole page at a time, safely.

DLQ (Dead-Letter Queue) — the "problem pile." Messages that can't be processed (broken, oversized, poison) are set aside here instead of jamming the line.

Idempotency / idempotency_key — a unique fingerprint per email (tenant, mailbox, provider_message_id) so a consumer can spot and ignore a duplicate.

At-least-once vs exactly-once — two delivery promises. Exactly-once (guaranteed one delivery) is impractical; mailflow does at-least-once (occasionally twice), which is why the key matters.

OIDC-JWT / JWKS — a signed token (JWT) proving a push came from Google; verified against Google's public keys (JWKS), checking signature, audience and issuer.

RFC822 — the raw text wire-format of an email (headers + body). Gmail hands this over raw; mailflow parses it.

Envelope / CleanEmail / EmailEvent — Envelope = parsed headers (from, to, subject…); CleanEmail = the cleaned message; EmailEvent = the packaged announcement handed to the consumer.

StreamRef / stream — a watched slice of a mailbox. Provider-defined: Gmail = one whole-mailbox stream; Outlook = one per folder.

thread_key — the ID grouping a conversation (email + replies). Gmail threadId / Outlook conversationId.

Fail closed / fail open — on uncertainty, "fail closed" rejects (safe); "fail open" lets it through (risky). The size guard must fail closed.

Backoff / jitter / Retry-After — when a server says "slow down," wait longer each retry (backoff), add randomness (jitter), and honor the server's Retry-After hint.

Error taxonomy (Auth / Permanent / Transient) — failure buckets: re-login, give-up-and-DLQ, or wait-and-retry.

Graph — Microsoft Graph, the API behind Outlook. "Graph" = Outlook throughout.

SecretProvider / token rotation — supplies login tokens; "rotation persistence" = saving a refreshed token so the next run still works.

DWD · DSAR · KMS · TNEF — Domain-Wide Delegation (multi-mailbox auth) · Data-Subject Access Request (GDPR) · Key Management Service (encryption) · a legacy Outlook attachment format. All out of V1.

Fencing / leases — coordination locks that stop two workers double-processing the same item. Only needed once mailflow runs multi-worker (P2); V1 is single-worker so they're deferred.

POC — proof of concept: an early build to validate the approach, not yet production-hardened.

OOO — out-of-office auto-reply. Detecting these (and bounces) is the P2 bounce/OOO engine.

@provisional / @stable — markers on a port saying whether its shape is safe to build on (stable) or may still change (provisional).
